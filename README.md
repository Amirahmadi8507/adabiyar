# ادبیار — نسخه محلی Full-stack

پلتفرم فارسی یادگیری ادبیات با رابط RTL، افکت‌های اسکرول سه‌بعدی، کارت‌های پایه هفتم تا دوازدهم، بک‌اند Node.js/Express، دیتابیس SQLite، ورود امن مبتنی بر نشست، نقش دانش‌آموز/معلم/مدیر، ساخت و شرکت در آزمون و اتصال اختیاری به API هوش مصنوعی.

## پیش‌نیازها
- Node.js نسخه 20 یا جدیدتر (ترجیحاً LTS)
- اینترنت فقط برای نصب بسته‌ها و درخواست به ارائه‌دهنده هوش مصنوعی لازم است؛ خود سایت و دیتابیس روی سیستم شما اجرا می‌شوند.
- Docker لازم نیست.

## اجرا در Windows 10/11 با PowerShell

1. ZIP را Extract کنید؛ وارد پوشه `vazhnegar-site` شوید (همان پوشه‌ای که `package.json` دارد).
2. بررسی کنید Node نصب است:
   ```powershell
   node -v
   npm -v
   ```
3. بسته‌ها را نصب کنید:
   ```powershell
   npm install
   ```
4. فایل تنظیمات را بسازید:
   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```
5. در `.env` مقدار `SESSION_SECRET` را به یک رشته تصادفی طولانی تغییر دهید و `ADMIN_PASSWORD` را به یک گذرواژه قوی با حداقل ۱۲ نویسه تغییر دهید. این کار را **قبل از اولین اجرا** انجام دهید. مدیر اولیه در شروع اول ساخته می‌شود.
6. سرور را اجرا کنید:
   ```powershell
   npm start
   ```
7. در مرورگر به `http://localhost:3000` بروید. پنجره PowerShell را باز نگه دارید؛ با `Ctrl+C` سرور متوقف می‌شود.

داده‌ها و فایل نشست در پوشه `data` کنار پوشه پروژه ساخته می‌شوند، نه در پوشه عمومی سایت. حذف این پوشه دیتابیس و کاربران را پاک می‌کند؛ قبل از حذف از آن نسخه پشتیبان بگیرید.

## ورود مدیر اولیه
ایمیل و گذرواژه از مقادیر `ADMIN_EMAIL` و `ADMIN_PASSWORD` در `.env` خوانده می‌شوند. مقادیر نمونه فقط برای راه‌اندازی محلی هستند؛ حتماً آن‌ها را عوض کنید. مدیر فقط در صورتی خودکار ساخته می‌شود که هنوز هیچ مدیری در دیتابیس وجود نداشته باشد. اگر مدیر ساخته نشد، مطمئن شوید گذرواژه حداقل ۱۲ نویسه است و دیتابیس قبلی را بررسی کنید.

## فعال‌سازی هوش مصنوعی رایگان با Ollama (محلی)
برای اجرای مدل روی لپ‌تاپ بدون API Key پولی:
1. Ollama را از https://ollama.com/download/windows نصب کنید.
2. در PowerShell مدل سبک را دریافت و آزمایش کنید: `ollama run qwen2.5:1.5b`
3. فایل `.env` را باز کنید و این تنظیمات را قرار دهید:
   ```env
   AI_PROVIDER=ollama
   OLLAMA_BASE_URL=http://127.0.0.1:11434
   OLLAMA_MODEL=qwen2.5:1.5b
   ```
4. مطمئن شوید Ollama فعال است؛ سپس سرور سایت را با `Ctrl+C` متوقف و دوباره `npm start` کنید.
5. صفحه سایت را باز کنید، وارد حساب شوید و «معلم هوشمند» را امتحان کنید.

Ollama در این حالت روی همین کامپیوتر اجرا می‌شود؛ به API Key نیاز ندارد و برای استفاده از مدل پس از دانلود، اینترنت لازم نیست. پاسخ اول ممکن است روی CPU زمان ببرد. مدل‌ها فضای دیسک مصرف می‌کنند. برای بررسی API می‌توانی `http://localhost:11434` را از همان کامپیوتر آزمایش کنی؛ endpoint چت در `/api/chat` است.

## فعال‌سازی هوش مصنوعی با APIهای ابری (اختیاری)
برای استفاده از یک سرویس ابری، در `.env` فقط **یک** ارائه‌دهنده را انتخاب و کلید همان را وارد کنید. در حالت `off` قابلیت‌های غیرهوش مصنوعی اجرا می‌شوند؛ بخش معلم هوشمند غیرفعال می‌ماند:

### OpenAI (ChatGPT models via API) — انتخاب پیش‌فرض این نسخه
```env
AI_PROVIDER=openai
OPENAI_API_KEY=کلید_واقعی_خودت
OPENAI_MODEL=gpt-4.1-mini
```
کلید را از https://platform.openai.com/api-keys دریافت کنید. دسترسی مدل و اعتبار API به حساب شما بستگی دارد و ممکن است استفاده هزینه داشته باشد. اگر فایل `.env` را قبلاً ساخته‌اید، تغییر `.env.example` آن را به‌روزرسانی نمی‌کند؛ مقدار `AI_PROVIDER` را مستقیماً در `.env` روی `openai` بگذارید.

### Gemini
```env
AI_PROVIDER=gemini
GEMINI_API_KEY=کلید_واقعی_خودت
GEMINI_MODEL=gemini-3.8-flash
```
کلید را از Google AI Studio دریافت کنید و مدل/سهمیه در دسترس حساب خود را در مستندات فعلی ارائه‌دهنده بررسی کنید.

### Groq
```env
AI_PROVIDER=groq
GROQ_API_KEY=کلید_واقعی_خودت
GROQ_MODEL=llama-3.3-70b-versatile
```

### OpenRouter
```env
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=کلید_واقعی_خودت
OPENROUTER_MODEL=openrouter/auto
```

بعد از ذخیره `.env` سرور را با `Ctrl+C` متوقف و دوباره `npm start` کنید. کلیدها فقط سمت سرور مصرف می‌شوند و نباید در `public/app.js` یا Git قرار بگیرند. استفاده از API ممکن است هزینه یا محدودیت سهمیه داشته باشد؛ این پروژه تضمین نمی‌کند که API رایگان باشد.

## تغییرات نسخه ۱.۱

### باگ‌های رفع‌شده
- **ارسال آزمون در ایران همیشه رد می‌شد**: زمان شروع (UTC) در بخش ارسال به‌اشتباه به‌وقت محلی سرور خوانده می‌شد؛ در منطقه‌ی زمانی UTC+3:30 همه‌ی ارسال‌ها «زمان تمام شده» اعلام می‌شدند.
- ثبت‌نام با ایمیل تکراری خطای ۵۰۰ می‌داد؛ حالا ۴۰۹ با پیام مناسب.
- کلیدهای خارجی (`ON DELETE CASCADE`) بعد از اولین ذخیره‌ی دیتابیس خاموش می‌شدند (رفتار `export()` در sql.js)؛ حالا بعد از هر ذخیره دوباره فعال می‌شوند.
- ذخیره‌ی دیتابیس اتمیک شد (فایل موقت + rename) و برای سرعت، با تأخیر کوتاه و یکجا انجام می‌شود. با Ctrl+C هم ذخیره می‌شود.
- دکمه‌ی «بازگشت» در نتایج پنل معلم لیست را خالی می‌کرد.
- یادداشت درس هنگام باز شدن خالی بود و یادداشت قبلی را بازنویسی می‌کرد.
- پاسخ‌های صحیح آزمون با درخواست مستقیم API پیش از پایان آزمون قابل مشاهده بود؛ سؤال‌ها فقط بعد از «شروع» به دانش‌آموز می‌رسند.
- محدودیت درخواست ورود، درخواست‌های عادی `/api/auth/me` را هم می‌شمرد و کاربران را قفل می‌کرد.
- نشست پس از ثبت‌نام بازسازی نمی‌شد (Session Fixation)، کلید Gemini در URL بود، زمان پاسخ ورود برای ایمیل ناموجود متفاوت بود، و ورودی نامعتبر (مثل پایه غیرعددی) خطای ۵۰۰ می‌داد.
- متن «نمایشی» معلم هوشمند و برچسب ثابت «محتوای نمونه» برای همه‌ی درس‌ها؛ حالت روشن سایت در نوار بالا و هیرو ناخوانا بود.

### قابلیت‌های جدید
- **دانش‌آموز**: داشبورد «پیشرفت من» (پیشرفت هر پایه، روزهای متوالی مطالعه، آزمون‌ها)، نشان‌کردن درس و شعر، مرور پاسخ‌های آزمون، ذخیره‌ی خودکار پاسخ‌ها و ادامه‌ی آزمون، تصحیح خودکار آزمونی که زمانش تمام شده، تغییر نام و گذرواژه.
- **معلم هوشمند**: گفت‌وگوی چندمرحله‌ای (حافظه‌ی ۶ پیام اخیر)، دکمه‌ی «بپرس از معلم هوشمند» روی هر درس و شعر، پیام‌های روشن برای خاموش بودن Ollama یا نصب‌نبودن مدل، و اعتبارسنجی خروجی تولید سؤال.
- **سایت**: فیلتر و جست‌وجوی شعر (شاعر، متن، پایه)، «بیت امروز»، ذخیره‌ی پوسته‌ی تیره/روشن، اعلان‌های کوتاه، نشانگر بخش فعال در منو.
- **معلم**: ویرایش مشخصات آزمون، ویرایش و حذف سؤال، بازگرداندن آزمون به پیش‌نویس (تا وقتی کسی شرکت نکرده)، بایگانی و حذف آزمون، آمار (میانگین، بیشترین/کمترین، درصد پاسخ صحیح هر سؤال)، خروجی CSV برای Excel.
- **مدیر**: جست‌وجوی کاربران، فعال/غیرفعال‌سازی حساب، تنظیم گذرواژه‌ی جدید، دانلود نسخه‌ی پشتیبان دیتابیس.
- **زیرساخت**: نشست‌های ماندگار، `TRUST_PROXY` و `COOKIE_SECURE`، امتناع از اجرا در production با `SESSION_SECRET` ضعیف، بررسی `Sec-Fetch-Site` برای CSRF، تست API یکپارچه (`test/api.test.js`).

## قابلیت‌های پیاده‌سازی‌شده
- ثبت‌نام با ایمیل و گذرواژه، ورود/خروج و نشست HTTP-only؛ نقش‌ها: دانش‌آموز، معلم، مدیر.
- SQLite از طریق sql.js (WebAssembly، بدون نیاز به کامپایل native) با ساخت خودکار جداول و ذخیره فایل پایگاه داده بین اجراها. نشست‌های ورود در فایل `data/sessions.json` ذخیره می‌شوند و با راه‌اندازی مجدد سرور پاک نمی‌شوند.
- جست‌وجوی درس‌ها بر اساس پایه، نکات و واژگان نمونه، ثبت پیشرفت و یادداشت شخصی.
- معلم/مدیر: ساخت آزمون پیش‌نویس، افزودن سؤال چندگزینه‌ای، انتشار آزمون؛ دانش‌آموز: شروع آزمون و ارسال پاسخ؛ نمره سؤال‌های چندگزینه‌ای سمت سرور محاسبه می‌شود.
- نتایج و ارسال‌ها، مسیر بررسی پاسخ‌های تشریحی، تغییر نقش کاربران توسط مدیر.
- معلم هوشمند و تولید سؤال اختیاری با Ollama محلی، OpenAI، Gemini، Groq یا OpenRouter.
- Helmet، محدودیت درخواست ورود و AI، هش گذرواژه، اعتبارسنجی ورودی و کنترل نقش سمت سرور.

## محدودیت‌های مهم و صداقت محتوایی
- درس‌های نمونه داخل دیتابیس فقط برای آزمایش مسیرهای سایت هستند؛ **فهرست رسمی و کامل کتاب‌های فارسی پایه هفتم تا دوازدهم نیستند**. عنوان درس‌ها، نکات و منابع رسمی باید توسط مدیر/متخصص بررسی و وارد شوند. وضعیت محتوا در دیتابیس به‌عنوان `demo` ثبت می‌شود.
- ورود با شماره موبایل و پیامک پیاده‌سازی نشده؛ برای آن به ارائه‌دهنده واقعی SMS و تأیید شماره نیاز است.
- زمان آزمون و تلاش دانش‌آموز سمت سرور کنترل می‌شود و پاسخ‌ها خودکار ذخیره می‌شوند؛ اما این نسخه چند تلاش برای یک آزمون، سؤال تشریحی و نمره‌دهی دستی ندارد (فقط سؤال تستی).
- مسیر تولید سؤال هوش مصنوعی صرفاً پیش‌نویس سؤال می‌دهد؛ معلم باید خروجی را بازبینی کند. مدل‌ها و دسترسی API ممکن است تغییر کنند.
- پیش از استفاده عمومی/اینترنتی، تست امنیتی، سیاست حریم خصوصی، پشتیبان‌گیری، HTTPS، مدیریت خطا و بازبینی کامل مجوزها لازم است. این نسخه برای اجرای محلی و نمونه دانشگاهی آماده شده، نه استقرار عمومی بدون بازبینی.

## ساختار پروژه
- `server.js` — API و منطق سرور؛ پایگاه داده با `sql.js` و بدون `better-sqlite3`/`connect-sqlite3`
- `public/index.html` — ساختار صفحه
- `public/styles.css` — طراحی و انیمیشن‌ها
- `public/app.js` — تعاملات رابط و اتصال API
- `public/assets/literature-background.jpg` — بک‌گراند هنری (فقط تصویر، بدون UI روی آن)
- `.env.example` — نمونه تنظیمات (کلید واقعی در این فایل قرار ندهید)
- `data/` — دیتابیس و نشست‌ها هنگام اجرا

## پنل‌های آموزشی (نسخه تکمیلی)
- پنل معلم: `http://localhost:3000/teacher`
- پنل مدیر: `http://localhost:3000/admin`
- آزمون تستی: ساخت پیش‌نویس، افزودن سؤال‌های چهارگزینه‌ای، انتشار پس از حداقل ۵ سؤال، زمان‌سنج سمت سرور، تلاش ثبت‌شده برای هر دانش‌آموز، تصحیح خودکار و نمایش نتایج.
- مدیر می‌تواند نقش کاربران، درس‌ها و شعرها را مدیریت کند. کتابخانه ۳۰ شعر با نکات ادبی و دستوری دارد.
- برای اولین مدیر، قبل از اولین اجرا در `.env` مقدارهای `ADMIN_EMAIL` و `ADMIN_PASSWORD` (حداقل ۱۲ نویسه) را تنظیم کنید. اگر پایگاه داده قبلاً ساخته شده و مدیر ندارد، از حساب مدیر موجود/دستورالعمل بازیابی استفاده کنید؛ متغیرهای اولیه فقط هنگام ایجاد اولین مدیر اعمال می‌شوند.
- برای تبدیل دانش‌آموز به معلم: وارد پنل مدیر شوید و نقش کاربر را تغییر دهید.
- نکته محتوایی: درس‌ها و شعرها یک بسته آموزشی تکمیلی هستند و پیش از استفاده رسمی باید عنوان‌ها، ضبط شعر، انتساب و نکات با نسخه رسمی کتاب و منبع معتبر تطبیق داده شوند؛ پروژه ادعای رونویسی کامل کتاب‌های درسی را ندارد.
